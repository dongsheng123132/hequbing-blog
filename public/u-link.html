开源项目 · Apache-2.0 · v0.5.1

两台机器，装上就能互控和调试
不需要公网 IP，也不需要 Tailscale

U-Link Core 是一套自己托管的远程执行层：每台机器主动向外连你自己的 relay，运维或 AI agent 就能跑命令、传文件、看屏幕并留下审计。带 macOS 菜单栏和 Windows 托盘常驻程序，一个状态点就知道在不在线。

在 GitHub 看源码与文档 → 下载 Release（含桌面端） 看 10 分钟怎么搭

公开版是 alpha：发布二进制未做代码签名，Windows SmartScreen / macOS Gatekeeper 可能提示；用 Release 里的 SHA256SUMS 校验后再打开，或直接 make link 自己编译。没有官方托管 relay，需要你自己部署。详见安全说明。

它解决什么

开发者在 Mac 上写代码，需要在家里或办公室那台 Windows 上编译、看日志、抓一屏；或者内部 IT 要在员工明确同意的机器上做一次可审计的维修。目标机器一般在 NAT 后面、没有公网 IP、也没开 SSH。

目标机只出站

agent 主动 wss 连你的 relay，不用开入站端口、不用改路由器、不依赖组网产品。把 relay 放在一台能访问的 Linux 上即可。

CLI / JSON / MCP

命令、文件、截图、审计都有命令与结构化输出；ulink mcp 让 Claude Code、Codex 等 AI agent 直接调用同一套操作。

桌面常驻

macOS 菜单栏 / Windows 托盘的状态点 + 本地控制台：设备列表、流式终端、设置、一键自检、添加设备命令，都在浏览器里。

配对才上线

每台机器一把 Ed25519 密钥，首次注册显示 6 位码，需运维审批；同一设备 ID 换公钥直接拒绝，可随时吊销。

每次操作留痕

远程命令写本地 JSONL 审计；日志里疑似凭据会打码。文件传输限制在允许的目录内。

自己掌控数据

relay 是 Go 单二进制、无状态、Docker 一条命令起。没有账号、没有云依赖、没有遥测；TLS 证书 pin 由你自己分发。

架构

桌面程序把「被控端 agent」和「控制端 controller」合在一个进程里，所以两台都装上就能互控。

[ CLI / MCP / 控制台 ] --wss--> [ 你自建的 relay ] <--wss-- [ 每台机器上的 agent ] devices · run · audit 设备密钥 · 配对码 exec · files · screen TLS + token 目标机永远不需要开入站端口：两端都主动向外拨号。 外置 IP-KVM（PiKVM / NanoKVM）适配器可选，用于 BIOS / 黑屏阶段。

10 分钟搭起来

完整方法写在仓库的 relay 部署 Skill 里（AI agent 也能直接读）。简版如下。

  1. 1. 起 relay：git clone 后进入 deploy/relay，cp .env.example .env，填两个随机长 token，保持 REQUIRE_DEVICE_KEYS=1。
  2. 2. 签证书：openssl req -x509 ...，subjectAltName 必须覆盖客户端实际用的域名或 IP；记下 openssl x509 -fingerprint -sha256 的指纹。
  3. 3. 启动：docker compose up -d --build，curl -k https://127.0.0.1:8900/health 返回 ok。
  4. 4. 两台机器装好：桌面端「设置」里填 relay、两个 token、TLS 指纹；或用「添加设备」生成命令在另一台执行。
  5. 5. 审批配对：新设备显示 6 位码，运维 ulink pair approve <码>；「一键自检」全绿即完成。

常见坑：证书 SAN 与拨号地址不符（尤其 IP 变了）、自签证书没填 TLS pin、把两个 token 填反、代理挡住 wss。控制台的自检会逐项给出原因和下一步。

边界：它不是什么

不是远程桌面

不提供完整 GUI 远控，那是 MeshCentral / RustDesk 的领域。这里主打命令、文件、截图和 AI 工作流。

不是完整企业 RMM

没有 RBAC / SSO / 多租户 / 补丁管理 / 批量部署。控制器目前是单一全局 token，relay 到客户端之间没有 payload 端到端加密。

不是给客户装的远控后门

只用于自己拥有的机器，或员工明确同意的设备；配对需要人审批，连接状态在桌面端可见可停。

安全模型、令牌权限边界、未签名构建的说明都在仓库 SECURITY.md。

常见问题

有官方 relay 可以直接连吗？

没有。这是自托管项目，每套安装都要自己部署 relay；好处是数据、证书、token 都在你手里。仓库里给了 Docker 部署方法。

和 Tailscale 是什么关系？

不用 Tailscale，也能和它共存。U-Link 是应用层中继：两端主动连同一个 relay，不建立虚拟网卡。自建 relay 是唯一额外要准备的东西。

为什么下载后被系统拦截？

发布二进制未签名（开源项目，没有采购代码签名证书）。请用 Release 的 SHA256SUMS 校验；macOS 可执行 xattr -dr com.apple.quarantine /Applications/U-Link.app，Windows 在确认哈希后选择仍要运行。最稳妥是从源码 make link 自己编译。

内网 IP 变了就连不上？

会。pin 模式会校验证书对拨号地址是否有效：用 IP 访问时证书必须有对应 IP SAN，IP 变化要重签证书并更新客户端的 pin。用固定域名 + 受信任 CA 证书可避开这一类问题。

IT 给员工电脑配对方便吗？

小团队（几台到十几台）够用：员工端运行后显示 6 位码，微信发回，IT 审批一次即可，之后重连不用再配。但 20–200 台的批量装机体验还不行：目前没有 MSI 安装包、没有域策略批量下发、没有按人分权与会话时长控制。这部分属于后续企业版，不在当前开源核里。

可以商用吗？

Apache-2.0，可以。但请自行评估是否适合你的合规要求：当前是 alpha，未签名、无第三方审计、控制端为单 token。
